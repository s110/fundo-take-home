# LLM reviewer for keyword transaction labels

An LLM reviews the labels of a keyword engine on Plaid bank transactions, flags the ones it doubts with a
reason an underwriter can act on, and a release gate decides when a new prompt or model may go live.

Read `SOLUTION.md` first. `EVAL.md` is the evaluation contract (objectives, SLOs, gate thresholds), and
`DECISIONS.md` gives the reason for each piece.

Python 3.9 or later, standard library only. Nothing to install.

## 1. Re-generate every output from the cache (no API key, no network)

```bash
git clone <this repository> && cd <its directory>
python3 run.py --offline
git status --porcelain        # empty output = every committed file regenerated byte for byte
```

It takes about 20 seconds. It writes the data, runs the keyword engine and the reviewer for both models
on both splits, scores them, computes the credit features and offers, runs the mislabel simulation and
the release gate. Every model reply comes from `cache/llm_responses.jsonl`. With `--offline`, a prompt
that is not in the cache acts like a provider outage: the keyword label stays, and the pattern is marked
`unreviewed`.

## 2. Run with the model

The models are Claude Haiku and Claude Sonnet through the Claude Code CLI (`claude`, logged in, or with
an API key):

```bash
export ANTHROPIC_API_KEY=...                          # optional; without it the CLI uses its logged-in account
python3 run.py --provider haiku --split dev           # one run; only prompts that are not in the cache are sent
python3 run.py                                        # every run; same as --offline while the cache is complete
```

## 3. The release gate

```bash
python3 gate.py runs/haiku/dev runs/sonnet/dev                                              # stages 1-2
python3 gate.py runs/haiku/dev runs/sonnet/dev runs/haiku/holdout runs/sonnet/holdout       # + stage 3
```

Exit code 0 means MERGE or PROMOTE. CI (`.github/workflows/gate.yml`) runs step 1 on every push and the
gate against the base branch on every pull request.

## 4. Your own transactions

```bash
python3 review.py their_file.json --name "Acme LLC" --owner "Jane Doe" --industry restaurant
```

One Plaid `/transactions/get` response. It prints each pattern the reviewer changed or sent to a person,
and the features and offer before and after. Missing `original_description`, `personal_finance_category`
or `accounts` are filled in with a warning. Nothing is scored, because there is no ground truth.

## What is where

| path | content |
|---|---|
| `runs/summary.md` | every run side by side, and the model spend |
| `runs/<model>/<split>/report.md` | the numbers of one run: hard rules, revenue, injections, features and offers, scenarios |
| `runs/<model>/<split>/errors.md` | every label still wrong after review, with the model's reason |
| `runs/<model>/<split>/decisions.jsonl` | one line per transaction: keyword label, model suggestion, action, final label |
| `runs/<model>/<split>/calls.jsonl`, `patterns.jsonl` | one line per model call, and per pattern (what the gate reads) |
| `runs/<model>/<split>/metrics.json` | the same numbers, plus the manifest (input, prompt and reply hashes) |
| `runs/gate/` | the gate report for each candidate |
| `runs/sensitivity.md` | how random mislabels move the features and the offer |
| `data/<split>/` | synthetic Plaid responses, application data, ground truth (only `fundo/evaluate.py` reads it) |
| `fundo/generate.py` | the data generator; every business and its risk cases are described there |
| `fundo/engine.py` | the legacy keyword engine, imperfect on purpose |
| `fundo/reviewer.py` | patterns, prompt, validation, retry, decision policy |
| `fundo/llm.py` | the model call and the cache |
| `fundo/evaluate.py`, `fundo/credit.py` | metrics; features, the offer rule, the mislabel simulation |
